# [Codelab Starter] Deploy, Contain, Observe: Least-Privilege ADK Agents on Agent Runtime, from Sandbox to Trace

The starter project for the Deploy, Contain, Observe codelab. You work on a spending-insights agent for Cymbal Wallet, a fictional digital wallet app. The agent is built with the Agent Development Kit (ADK), reads BigQuery through MCP Toolbox, and writes and runs Python to chart a customer's spending. It deploys to Agent Runtime with Agents CLI.

The agent here works, and it is deliberately open:

- `UnsafeLocalCodeExecutor` runs the model's code on your machine, as you, with your files and your network.
- The deployed agent has no identity of its own yet that can call MCP Toolbox, and it holds a project-wide `roles/aiplatform.user` it does not need.

The codelab walks you through fixing both.

## Requirements

- A Google Cloud project with billing enabled

## Run it

From Cloud Shell, in this folder, at least 15 minutes before you start the codelab:

```bash
cp .env.example .env
sed -i "s/your-project-id/$(gcloud config get-value project)/" .env # Set up .env with your project ID
scripts/setup.sh            # APIs, data, MCP Toolbox, and the first deploy to Agent Runtime
```

The first deploy takes 5 to 10 minutes. Then:

```bash
scripts/check.sh            # Prints READY, or names what is missing
uv run adk web              # Dev UI on port 8000, open it with Web Preview
```

Open `/dev-ui/?app=spending_agent` to chat with the agent.

MCP Toolbox runs in the background on 127.0.0.1:5000. Run `scripts/toolbox.sh status` to check it.

## Files

| Path | What it is |
|---|---|
| `spending_agent/agent.py` | The agent, its instruction, the MCP Toolbox connection and the code executor |
| `spending_agent/fast_api_app.py`, `spending_agent/app_utils/` | The server Agent Runtime runs, generated by Agents CLI |
| `mcp-toolbox/tools.yaml` | The BigQuery source and the tools the agent can call |
| `data/seed.sql` | The synthetic Cymbal Wallet data `setup.sh` loads into BigQuery |
| `Dockerfile`, `agents-cli-manifest.yaml` | What `agents-cli deploy` builds and deploys |
| `deployment_metadata.json` | Written by `agents-cli deploy`: which Agent Runtime instance is yours |
| `scripts/setup.sh` | One-time setup. Rerunning it also resets the data |
| `scripts/check.sh` | Prints `READY` or names what is missing |
| `scripts/toolbox.sh` | `start`, `restart`, `stop`, or `status` for MCP Toolbox |
| `scripts/engine.py` | Prints the agent's principal, warms up a sandbox, or deletes the agent |
| `scripts/cleanup.sh` | Deletes what the lab created |
| `solution/` | Finished files and one catch-up script per module. See its README |

The finished version of every file is in [solution/](solution/), with one script per codelab module. If a module goes wrong, run its script and carry on: `solution/2-sandbox.sh`, for example.

## The data

Everything in `data/seed.sql` is mock data for the codelab.

## Clean up

When you finish, run `scripts/cleanup.sh`, or delete the project. Deleting the agent does not remove the project roles its identity holds, and the script removes those too.
